# Frontend API Gaps

## Current Status

The iOS frontend can already render real posts from the existing API:

- `GET /posts?limit=20&offset=0`
- `GET /posts/{post_id}`
- Static images under `/images/{filename}`

The current response is enough for a basic feed card:

```json
{
  "id": 4,
  "title": "HN spotlight: Starring the Computer",
  "description": "A short summary.",
  "content": "Longer generated post body.",
  "image_url": "/images/post-4.png",
  "source_name": "hacker_news",
  "source_item_id": "48796093",
  "source_url": "https://example.com/article",
  "created_at": "2026-07-06T07:52:25.654423"
}
```

The frontend currently fills the missing UI fields locally. These gaps are not blocking the app from working, but they should be addressed when the feed needs real filtering, engagement metadata, or server-backed presentation data.

## Gaps To Address Later

### 1. Categories

The frontend has a `Today` feed only for now because posts do not include a category.

Add a backend `category` field when category tabs should become real.

Suggested categories for v1:

- `technology`
- `science`
- `markets`
- `culture`

Implementation options:

- Store `category` on `GeneratedPost` if it is generated by the AI pipeline.
- Store `category` on `SourceItem` if it comes from source classification before generation.
- Return `category: null` for old rows only if a migration is not done immediately.

Preferred shape:

```json
{
  "category": "technology"
}
```

### 2. Source Engagement Counts

The current card UI no longer displays real counts because the API does not return them.

For Hacker News, the database already stores useful source metadata:

- `SourceItem.score` can become `score`.
- `SourceItem.raw_json["descendants"]` can become `comment_count`.

Preferred shape:

```json
{
  "score": 212,
  "comment_count": 47
}
```

Do not name these fields `likes` unless the backend is actually tracking app-specific likes. Hacker News score is source engagement, not NextNews likes.

### 3. Absolute Image URLs

The current API returns relative image paths like:

```json
{
  "image_url": "/images/post-4.png"
}
```

The iOS app can resolve this against its configured API base URL, so this is not urgent.

If the API will be consumed by multiple clients, consider adding an absolute image URL:

```json
{
  "image_url": "http://127.0.0.1:8000/images/post-4.png"
}
```

Only do this if the API has a reliable configured public base URL. Otherwise, keep relative URLs.

### 4. Server-Side Search And Filtering

The frontend currently searches locally over the loaded posts.

Add server-side query parameters only when the feed grows beyond one page or needs backend-backed category tabs:

```http
GET /posts?limit=20&offset=0&query=zig&category=technology
```

Suggested behavior:

- `query` searches generated `title`, `description`, and `content`.
- `category` filters by the future category field.
- Existing `limit` and `offset` behavior stays unchanged.

### 5. Detail-Specific Fields

`PostDetail` currently matches `PostListItem`.

Keep that until the detail screen needs more data. Later detail-only fields could include:

- `image_prompt`
- source author
- source score
- source comment count
- original source metadata

Do not add these to the list response unless the feed card needs them.

## Suggested Future Response Model

When the backend is ready to support the full feed UI, extend `PostListItem` to:

```json
{
  "id": 4,
  "title": "HN spotlight: Starring the Computer",
  "description": "A short summary.",
  "content": "Longer generated post body.",
  "image_url": "/images/post-4.png",
  "source_name": "hacker_news",
  "source_item_id": "48796093",
  "source_url": "https://example.com/article",
  "created_at": "2026-07-06T07:52:25.654423",
  "category": "technology",
  "score": 212,
  "comment_count": 47
}
```

## Recommended Backend Work Order

1. Add `score` and `comment_count` to the response from existing `SourceItem` data.
2. Add focused API tests that assert these fields are returned for seeded Hacker News rows.
3. Decide where category should be produced and stored.
4. Add `category` to the database model, generation pipeline, schemas, and tests.
5. Add optional `query` and `category` parameters to `GET /posts` once the frontend needs server-side filtering.

## Fields To Avoid In The API

Keep purely presentational fields in the frontend unless there is a strong product reason to centralize them:

- SF Symbol names
- gradient colors
- badge colors
- placeholder labels
- card layout hints

These are UI concerns and can be derived from `source_name` or `category` in the iOS app.
